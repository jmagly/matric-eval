# matric-eval Supported-Capability Roadmap

**Last reconciled**: 2026-08-03

**Latest released version**: 0.1.0

**Current delivery target**: 0.2.0

This document describes the capabilities supported by the current repository and
the work that remains before the next release. The Gitea tracker and milestones
are the delivery source of truth. Registry state is generated by the CLI rather
than maintained as a second hand-written benchmark inventory.

## Status Definitions

- **Stable**: registered for normal execution with a pinned protocol and automated
  tests. Stable does not mean every provider/model combination has been run in a
  production environment.
- **Gated**: integrated, but execution requires an official external runner,
  licensed/restricted data, special hardware, or another documented prerequisite.
- **Experimental**: runnable for research, but its protocol or integration contract
  is not yet a stable compatibility promise.
- **Unavailable**: retained in the registry to record a deliberate no-go decision.
- **Production validated**: exercised through a retained real-provider workflow in
  addition to deterministic tests.
- **Deferred**: tracked but excluded from the current release until its issue's
  promotion trigger is met.

## Current Baseline

The registry snapshot on 2026-08-03 contains **39 benchmarks**: 24 stable, 13
gated, one experimental, and one unavailable. Reproduce the inventory and audit
instead of copying these counts into downstream documents:

```bash
uv run matric-eval list-benchmarks
uv run matric-eval audit-benchmarks --fail-on-error
```

The offline audit reports 39 entries with zero metadata/protocol errors or
warnings. The current stable set is:

- Core and application benchmarks: ARC, DS-1000, GSM8K, HumanEval, IFEval,
  LiveCodeBench, matric-cli, matric-memory, MBPP, MMLU, MT-Bench, and Tool Calling.
- Successor, multimodal, and security benchmarks: CyberSecEval, HumanEval+,
  MBPP+, MMLU-Pro, MMMU, MMMU-Pro, and RealWorldQA.
- Repository and long-context benchmarks: BABILong, InfiniteBench, SWE-bench
  Verified, SWE-bench Pro, and SWE-bench Multilingual.

The gated set is Claw-Eval, GAIA, GAIA2, HELMET, MemoryBench, NL2RepoBench,
NoLiMa, OmniDocBench, QwenClawBench, RULER, Terminal-Bench, Tulving episodic
memory, and Video-MME-v2. InjecAgent is experimental. QwenWebBench is unavailable
until a reproducible public evaluator and dataset contract exists.

Protocol details and immutable revisions are recorded in the
[Wave 1](../benchmarks/wave1-protocols.md),
[Wave 2](../benchmarks/wave2-protocols.md), and
[Wave 3](../benchmarks/wave3-protocols.md) records.

## Supported Platform Capabilities

| Capability | Current support | Evidence and limits |
|---|---|---|
| Tiered execution | Smoke, quick, and full selection are implemented; per-benchmark registry metadata can override default sample counts | CLI and registry tests; use `list-benchmarks` for the current inventory |
| Providers | Ollama, llama.cpp, vLLM, OpenRouter, and Chutes provider adapters are implemented | Provider contract tests cover all adapters; retained real-provider evidence currently covers Ollama only |
| Scoring | Deterministic, code-execution, tool-calling, LLM-judge, multidimensional, and custom matric scorers | [Operational Validation v1](../validation/operational-validation-v1.md) records representative legacy scorer agreement |
| Checkpoint/resume | Interrupted runs persist completed benchmark results and resume pending work without duplicate completion | [Issue #87](https://git.integrolabs.net/roctinam/matric-eval/issues/87) and operational validation evidence |
| Parallel execution | Sequential and threaded result sets are equivalent for the pinned representative matrix | [Operational Validation v1](../validation/operational-validation-v1.md); this is not a universal provider throughput guarantee |
| CI | Gitea Actions enforces quality, test/coverage, smoke, and package-build gates on PRs and `main` | [Issue #88](https://git.integrolabs.net/roctinam/matric-eval/issues/88) |
| Real-provider smoke | Scheduled/manual Ollama workflow retains logs, results, checkpoints, and a model digest | [Issue #89](https://git.integrolabs.net/roctinam/matric-eval/issues/89), hosted run #51 |
| TypeScript client | Version 0.1.0 is published; the current source client builds and is tested | Clean 0.2.0 package validation is tracked by #93; matric-cli adoption is tracked by #94 |
| Rust client | No supported Rust binding in the current release | Deferred issue #96 requires a stable 0.2.0 schema and consumer approval |

The test inventory is intentionally not a timeless marketing count. On
2026-08-03, `pytest --collect-only` collected 2,307 tests; authoritative PR run
#52 completed 2,296 tests with 11 skips and 80.95% coverage. Use the current CI
run for release evidence.

## Reliability And Validation

The Reliability & CI Hardening milestone is complete:

1. [#87](https://git.integrolabs.net/roctinam/matric-eval/issues/87) connected checkpoint/resume to end-to-end execution.
2. [#88](https://git.integrolabs.net/roctinam/matric-eval/issues/88) made lint, formatting, tests, coverage, smoke, and builds authoritative in Gitea Actions.
3. [#89](https://git.integrolabs.net/roctinam/matric-eval/issues/89) added and executed a retained Ollama production smoke workflow.
4. [#90](https://git.integrolabs.net/roctinam/matric-eval/issues/90) recorded scorer parity and operational behavior.

The validation matrix reports 0.0 percentage-point variance for representative
HumanEval and MBPP scorer cases, 100% agreement for the pinned matric-memory title
and semantic cases, zero duplicate completed work on resume, and equivalent
sequential/threaded result sets. These are scoped contract checks, not a claim
that all models produce identical quality scores across implementations.
