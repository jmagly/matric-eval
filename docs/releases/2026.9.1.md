# matric-eval 2026.9.1

Release date: 2026-09-10 (UTC). Availability is established by a completed
[Gitea](https://git.integrolabs.net/roctinam/matric-eval/releases) or
[GitHub release](https://github.com/jmagly/matric-eval/releases), not by this
source file. No registry publication is enabled.

## Changes

- Import OBLITERATUS prompt datasets through a source registry that retains the
  original repository, revision, path, record identity and content digest. The
  accompanying qualification records keep prompt provenance distinct from later
  human-calibration choices.
- Make the preregistered Qwen3.8 TAU replay path safer and more diagnosable with
  bounded sandbox admission, simulator canaries, isolated service names,
  preserved manifest ordering and durable cleanup semantics.
- Record the cross-repository architecture for native ordered 1+ GPU
  allocations. The initial supported execution profiles are TP1 and TP2; this
  release contains the implementation plan, not a claim that multi-GPU TAU
  scoring is qualified.
- Introduce a schema-validated release configuration that makes build, CI,
  checked-tag, forge-mirror and published-asset gates explicit and repeatable.

## Compatibility and deferred work

Python 3.11+ and Node.js 18+ remain required. Package-version changes do not
alter the versioned result, protocol or evidence schemas.

TAU scoring and sandbox/integration research (#154), reusable grader
qualification against human calibration sets (#126), and remaining
OBLITERATUS dataset work (#164) stay deferred. Existing preregistration and
evidence-integrity boundaries remain in force; simulator success is not treated
as model-scoring evidence.

## Installation and verification

Use [the release guide](https://github.com/jmagly/matric-eval/blob/v2026.9.1/docs/development/releasing.md)
to download, verify and install a wheel or TypeScript tarball. PyPI and npm
registry publication remain disabled.

The candidate workflow must pass synchronized-version and archive checks,
SBOM/license/vulnerability review, and clean Python 3.11–3.14 consumer
validation. Each forge publishes its own verified bundle with source identity,
evidence reports and `SHA256SUMS`; failed validation cannot create a successful
release.
