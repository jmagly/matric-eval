# matric-eval 0.2.0

Version 0.2.0 packages the completed benchmark expansion and reliability work as
one supported release. The source tag, Python wheel/sdist, TypeScript package,
SBOMs, audit reports, license review, and checksum manifest are produced from the
same validated commit.

## Highlights

- 39 registry entries: 24 stable, 13 gated, InjecAgent experimental, and
  QwenWebBench explicitly unavailable.
- Completed Wave 1-3 protocol records covering successor, agentic, security,
  multimodal, repository, long-context, and memory benchmarks.
- Five provider adapters with retained real-provider validation for the Ollama
  smoke path.
- End-to-end checkpoint/resume with duplicate prevention and gap-only continuation.
- Authoritative Gitea CI and scheduled/manual real-provider smoke workflows.
- Representative legacy scorer agreement and sequential/threaded operational
  equivalence recorded in Operational Validation v1.

## Compatibility Notes

- Python support remains 3.11 and newer.
- `@matric/eval-client` continues to require Node.js 18 or newer.
- HumanEval now executes the canonical `check(candidate)` harness. Results from
  0.1.0-era runs that relied on syntax-only acceptance are not directly
  comparable without rerunning the benchmark.
- Benchmark lifecycle state is part of the support contract. Gated adapters need
  the official external runner, data access, hardware, or licensing prerequisite
  named in their protocol document.
- Result provenance includes framework and protocol revisions. Consumers must
  preserve unknown fields and should not rank incompatible protocol revisions.

## Installation

Python from the Gitea package registry:

```bash
python -m pip install \
  --index-url https://git.integrolabs.net/api/packages/roctinam/pypi/simple/ \
  matric-eval==0.2.0
matric-eval --version
```

TypeScript from the Gitea npm registry:

```bash
npm install \
  --registry https://git.integrolabs.net/api/packages/roctinam/npm/ \
  @matric/eval-client@0.2.0
```

## Verification

The release workflow retains the exact candidate bundle with:

- `matric-eval-0.2.0-release-bundle.tar.gz`
- `matric_eval-0.2.0-py3-none-any.whl`
- `matric_eval-0.2.0.tar.gz`
- `matric-eval-client-0.2.0.tgz`
- Python and npm CycloneDX SBOMs
- Python and npm vulnerability reports
- machine-readable and Markdown dependency-license reports
- version-surface report, release manifest, and `SHA256SUMS`

Extract the release bundle, then verify it before installation:

```bash
tar -xzf matric-eval-0.2.0-release-bundle.tar.gz
sha256sum --check SHA256SUMS
```

The release tag is created only after issue #93 validates those exact candidate
hashes in clean supported environments. The Gitea release links the validated
workflow run, package registries, source commit, and issue evidence.

## Known Limits

- Retained real-provider evidence covers Ollama; other providers have automated
  adapter contracts but are not claimed as production validated in this release.
- InjecAgent remains experimental and QwenWebBench remains unavailable.
- Two High transitive findings are accepted through 2026-09-30: Click's affected
  `click.edit()` API and protobuf's affected `ParseDict()` path are not used by
  matric-eval, and current Inspect dependency constraints prevent patched
  versions. The release gate rejects new, expired, mismatched, or Critical
  findings.
- The supported matric-memory Rust binding, static leaderboard/report generator,
  and provider-normalized token/cost accounting remain deferred under issues
  #96, #95, and #97 respectively.
- matric-cli adoption and rollback validation is completed separately under
  issue #94 after package publication.

Tag publication requires the repository `RELEASE_TOKEN` Actions secret to hold
a Gitea personal access token with repository and package write permissions.
Gitea 1.25 job tokens cannot authorize package uploads.
