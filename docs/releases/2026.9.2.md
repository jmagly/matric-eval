# matric-eval 2026.9.2

Release date: 2026-09-11 (UTC). Availability is established by a completed
[Gitea](https://git.integrolabs.net/roctinam/matric-eval/releases) or
[GitHub release](https://github.com/jmagly/matric-eval/releases), not by this
source file. No registry publication is enabled.

## Changes

- Make resident execution native to exact ordered 1+ GPU allocations across
  request, lease, scheduling, container visibility, vLLM parallelism, replay,
  reporting and cleanup. Registered TP1 and TP2 profiles fail closed when device
  count, order, topology, memory or observed runtime parallelism drifts.
- Add a bounded Basilisk TP2 qualification harness with topology/P2P evidence,
  content-free inference, typed TAU diagnostics and both controlled-success and
  injected-failure cleanup checks. Admission now rejects any selected GPU with a
  foreign CUDA process, even if its reported free memory is otherwise sufficient.
- Add an AIWG-wide agent-platform pipeline that derives its complete provider
  matrix from AIWG 2026.9.6, keeps direct endpoints separately classified, runs
  only through manual/scheduled/event DevOps entry points, and publishes a
  sanitized common evidence contract.
- Bound the agent pipeline with clean fixtures, pinned provenance, target-scoped
  environment variables, streaming redaction, JSONL/native-result validation,
  concurrency, per-attempt cost/token reservations, infrastructure-only retries,
  deadlines and process-group cancellation.
- Restore useful bounded real-provider smoke diagnostics and route Ollama
  inference through the supported OpenAI-compatible endpoint.

## Compatibility and incomplete qualifications

Python 3.11+ and Node.js 18+ remain required. Existing result and study evidence
schemas remain readable. The new agentic pipeline uses versioned
`matric-eval.agentic-pipeline/1` configuration and
`matric-eval.agentic-pipeline-result/1` output contracts.

The TP2 implementation and qualification harness are included, but this release
does not claim a successful two-A100 hardware qualification. Two bounded attempts
against the exact Basilisk GPU0/GPU2 NVLink pair failed closed before acquisition
because unrelated workloads occupied the pair. Issue #183 is marked blocked;
dependent operator documentation #184 and epic #178 remain open. No lease,
container, mount, canary, TAU run or owned CUDA allocation was created by the
failed admission.

TAU sandbox/scoring research (#154), reusable grader qualification (#126), and
remaining OBLITERATUS dataset work (#164) remain deferred. Simulator or pipeline
coverage records are not represented as model-scoring evidence.

## Installation and verification

Use [the release guide](https://github.com/jmagly/matric-eval/blob/v2026.9.2/docs/development/releasing.md)
to download, verify and install a wheel or TypeScript tarball. PyPI and npm
registry publication remain disabled.

The candidate workflow must pass synchronized-version and archive checks,
SBOM/license/vulnerability review, and clean Python 3.11–3.14 consumer
validation. Each forge publishes its own verified bundle with source identity,
evidence reports and `SHA256SUMS`; failed validation cannot create a successful
release.
